## 라벨링 단계

### 1. 포맷 변환

툴이 읽는 구조로 바꾼다. 포인트클라우드 `.npy` → `.pcd`(바이너리), 캘리브레이션 합성, 파일명 연번.
ASCII PCD 는 용량이 2 배라 쓰지 않는다.

### 2. 툴 설치

**SUSTechPOINTS** — 라이다와 카메라 4대를 같이 띄우고, 박스를 치면서 이미지 투영으로 바로 확인할 수 있다. 트랙 ID 지원.
labelCloud 는 설치가 쉽지만 카메라를 못 본다. CVAT 는 다중 카메라 설정이 복잡하다.

### 3. 박스 치기

박스 하나에 들어가는 것:

| 항목 | 내용 |
|---|---|
| 기하 | 위치 (x,y,z), 크기 (w,l,h), 방향 (yaw) |
| 클래스 | car, truck, pedestrian, bicycle … |
| 트랙 ID | 프레임 간 같은 객체 연결 |
| 속성 | 주차됨 / 이동중 / 정지중 |
| 가시성 | 가려진 정도 |

**ego pose 가 있으면 작업량이 크게 준다.** 주차된 차는 월드 좌표에 고정이므로 한 번만 그리면 각 프레임으로 변환된다. 프레임마다 다시 그려야 하는 것은 움직이는 객체뿐이다. pose 는 2단계에서 이미 나왔다.

### 4. 품질 검사

박스를 이미지에 투영해 물체에 맞게 올라가는지 본다. 3~5단계 보정이나 캘리브레이션이 틀렸으면 여기서 드러난다.

### 5. 데이터셋 정리

train/val 분할, 장소·조건 문서화. 좌표계는 **ego(또는 라이다) 기준**으로 저장한다 — 카메라가 4대 360° 라 KITTI 처럼 카메라 좌표계에 저장하면 어느 카메라 기준인지 정의되지 않는다. nuScenes 가 global/ego 에 저장하는 이유가 이것이다.

## 주의

- 실내 주차장이라 raw 평균 밝기가 **4.7/255** 다. 후처리로 끌어올렸지만 노이즈가 같이 커졌다. 다음 녹화부터는 `--exposure 30000 --gain 16` 을 쓸 것.
- free-run 이라 카메라-라이다 절대 시각에 ±20 ms 추정 오차가 남는다. 4 km/h 에서 2.3 cm 수준이라 3D 박스에는 충분하지만, 정밀 센서퓨전에는 MCU 동기화([`시간동기화`](../시간동기화), 94 µs)로 재촬영해야 한다.
- 모션 상관으로 시간 지연을 직접 재보았으나 실패했다. 두 센서 다 10 Hz 라 15 ms 를 분해하지 못한다 (세션별 추정치 +16 ~ +59 ms, 피크 상관 0.07~0.30).
