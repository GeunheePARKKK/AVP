# 라벨링 작업 방법 (12 단계)

ReBound 에서 검출기 초안을 확인·수정해 라벨을 만든다. **여기부터는 사람이 하는 작업이다.**

```bash
bash 데이터_라벨링/code/run_rebound.sh
```

---

## 작업 흐름

1. 메뉴 **Tools → "Add/Edit Annotations"** — 컨트롤 창이 하나 더 뜬다
2. **"Toggle Predicted or GT" 를 "Ground Truth" 로 변경** ← **반드시**
3. 박스 삭제 · 수정 · 추가
4. **"Save Changes"**

### 2 번을 반드시 해야 하는 이유

저장 위치가 토글에 따라 갈린다 (`annotation_editing.py:1351`).

| 토글 | 저장되는 곳 |
|---|---|
| Predicted | `pred_bounding/` — **비교용 예측 파일을 덮어쓴다** |
| **Ground Truth** | `bounding/` — 정답. **여기가 맞다** |

Predicted 로 두고 작업하면 "모델이 뭐라고 예측했는지" 와 "사람이 확정한 정답" 이 섞여 구분이 사라진다.

## 폴더 구조

```
rebound/session_025/
├── bounding/                 1,029 개  ← 여기서 작업. 초안이 복사돼 있다 (confidence 100)
├── pred_bounding/            1,029 개  ← 비교용 모델 예측
└── pred_bounding_original/   1,029 개  ← 백업. 건드리지 않는다
```

각 박스의 `data.pred_confidence` 에 원래 모델 점수가 남아 있다.

실수로 `pred_bounding` 을 덮어썼다면 되돌린다.

```bash
cd ~/ros2_ws/cam_lidar_recording/rebound/session_025
rm -rf pred_bounding && cp -r pred_bounding_original pred_bounding
```

## 조작법

창이 둘로 나뉜다. **클릭은 포인트클라우드 창, 값 입력은 컨트롤 창.**

### 포인트클라우드 창

| 작업 | 조작 |
|---|---|
| 시점 회전 | 좌클릭 드래그 |
| 시점 이동 | 우클릭 드래그 (트랙패드는 Ctrl + 좌클릭) |
| 확대 / 축소 | 휠 |
| **박스 선택** | **Ctrl + 좌클릭** — 반드시 **차의 점 위**를 클릭 |
| 박스 이동 | 선택 후 **Shift + 드래그** |

**빈 공간을 Ctrl + 클릭하면 선택이 풀린다.** 클릭 지점의 깊이로 대상을 찾기 때문에, 형상이 없는 곳을 누르면 "먼 평면" 으로 판정돼 해제된다 (`annotation_editing.py:481`).

선택되면 테두리가 굵어지고 중심에 좌표축이 뜨며 컨트롤 창의 Position · Scale 에 값이 찬다.

### 컨트롤 창

| 작업 | 위치 |
|---|---|
| 이동 축 전환 | "Toggle Translation/Rotation" — 수평(X,Y) ↔ 수직(Z) |
| 크기 | **Scale** 에 X, Y, Z 입력 |
| 위치 | **Position** 에 좌표 입력 |
| 클래스 | Properties → Annotation → **Class** |
| 박스 추가 | **"Add Bounding Box"** — 차량 중심에 생긴다 |
| 박스 삭제 | 선택 후 **"Delete Bounding Box"** |
| 저장 | **"Save Changes"** |

### 주의

- **회전 입력칸은 절대각이 아니라 "추가로 돌릴 각"** 이다. 30 을 넣으면 30° 가 되는 게 아니라 30° **더** 돌아간다.
- **드래그보다 숫자 입력이 확실하다.** 드래그는 커서 밑으로 박스를 통째로 옮기는 방식이라 시점이 기울어져 있으면 의도와 다르게 움직인다. 위에서 내려다보는 시점("Center Pointcloud View on Vehicle")에서 그나마 예측 가능하다.
- ID 는 읽기 전용이다. 현재 초안의 ID 는 `015_000` 같은 자동 생성값이라 트랙 ID 로 쓸 수 없다.

## 실제로 많이 하게 되는 일

초안이 이미 있으므로 대부분은 아래 순서다. 1 번이 제일 많고 드래그가 필요 없다.

1. **명백한 오탐 삭제** — 벽·기둥에 걸린 것, 차 두 대가 하나로 묶인 것
2. **위치가 어긋난 것 미세조정** — Position 에서 10~20 cm 단위로
3. **빠진 차 추가** — "Add Bounding Box" 후 Position / Scale / Rotation 입력
4. 클래스 확인 (car / truck)

## 범위

[`dataset_config.yaml`](dataset_config.yaml) 과 [`라벨링_가이드라인.md`](라벨링_가이드라인.md) 를 따른다. 요약하면:

- **20 m 이내만** 라벨링한다. 단 **그 안은 빠짐없이** — 빠뜨리면 모델이 맞게 찾아도 오탐으로 집계된다
- 박스는 타이트하게. 점을 밖으로 빼놓지 않는다
- 점이 적으면 카메라 영상으로 크기를 확인한다
- 기둥 · 벽 · 천장 · 바닥 표시는 라벨링하지 않는다

## 작업량 가늠

session_025 는 키프레임 28 장, 박스 1,029 개 (프레임당 37 개) 다.

다만 **조작 횟수는 그보다 훨씬 적다.** 주차된 차는 고정이라 한 번 맞추면 ego pose 로 전파된다. 실제 차는 50~80 대이고, 드리프트 때문에 5 초(키프레임 10 개)마다 재조정이 필요하다 (8 단계 측정).

**한 프레임을 끝까지 해보고 걸린 시간을 재면** 전체 일정이 나온다. 프레임당 20 분이면 28 장에 9 시간이다. 너무 길면 범위를 15 m 로 줄이거나 세션 수를 조정한다.
