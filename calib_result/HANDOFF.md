## 4. 알려진 한계 — 쓰기 전에 읽으세요

**(1) 높이(z)는 4대 중 3대가 줄자 입력값(-0.29 m)입니다.**
z 는 보드 법선 분포상 가장 약하게 결정되는 축(다른 축의 3~4배 불확실)이라 실측값으로
고정해 풀었습니다. 전방만 자유해로 -0.281 이 나와 줄자와 0.9 cm 차이였습니다.
**즉 z 는 검증된 값이 아니라 입력값**입니다. 카메라 4대가 정말 같은 높이인지 확인 필요.

**(2) 내부 파라미터 yaml ↔ 시리얼 매핑이 미확인입니다.**
`AVP_calib/cam{1..4}_calib` 4개가 어느 시리얼 것인지 기록이 없어 이름 순서로 대응시켰습니다.
재투영으로는 구분 불가(전부 2.33~2.36 px), 보드거리는 최대 1.17%(3.4 cm) 차이.
틀렸다면 위치에 3 cm 안팎 계통 오차. 다만 교차검증이 1~2 cm 로 맞아 크게 틀리지는 않은 듯.

**(3) 오른쪽 카메라의 좌우 기울기가 -30~+30° 로 제한적입니다.**
그래서 회전 불확실도가 0.683° 로 전방(0.289°)보다 큽니다. 더 올리려면 보드를 좌우로
40~50° 돌린 자세를 추가 수집해야 합니다.

**주의**: 이 값은 정지 상태 기준입니다. 주행 중에는 카메라-라이다 시각동기 오차와
라이다 모션왜곡(10 Hz 회전 = 20 km/h 에서 55 cm)이 이 오차보다 커질 수 있습니다.

## 6. 재현 / 재캘리브레이션

```bash
# 수집 (자동 촬영: 보드를 자세 바꿔 들고 가만히 있으면 저장)
python3 collect_calib.py --cam-sn <시리얼> --cam-name <이름> \
  --target target_aruco.yaml --params <내부파라미터.yaml> --exposure 90000 --auto

# 풀이
python3 solve_extrinsic.py --data calib_data/<이름> --params <내부파라미터.yaml> \
  --cam-pos <x> <y> <z> --yaw <deg> --fix-height -0.29 --out calib_result
```

**수집 조건** (실측으로 확인한 값)
- 거리 **1.8~2.5 m**. 더 멀면 보드(높이 0.61 m)에 걸리는 라이다 링이 3~6개로 떨어져 실패
- 게인 최소 + 노출 길게. 게인 0→16 dB 올리면 재투영 1.22→1.74 px 로 악화
- 화면 `board` 값(보드영역 평균밝기) 120~200. 전체 포화율은 천장조명이라 무의미
- 자세는 좌우·상하를 **동시에** 비틀어 격자를 고르게. 한 축씩만 돌리면 가운데만 촘촘해짐
- 법선 다양성 지수 **0.12 이상** 필요. 미만이면 solve_extrinsic 이 경고/중단

**USB 인덱스는 재연결마다 바뀝니다. 반드시 `--cam-sn` 으로 지정하세요.**
(2026-09-28 실제로 전방 카메라가 index 3 → index 2 로 바뀐 것을 확인)

## 7. 사용한 타겟

`target_aruco.yaml` — ArUco 4개(DICT_4X4_250, id 0/1/2/3) + 원형 구멍 3개 보드.
마커 150 mm, 가로 전체폭 790 mm, 세로 전체높이 530 mm (줄자 실측).

100~103, 전체폭을 780x520 으로 적고 있으나 **둘 다 실제와 다릅니다.**
