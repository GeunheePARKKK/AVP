## 10. 초안 다듬기 (신설)

`refine_boxes.py` — 검출기 출력을 시간 일관성과 모양으로 다듬는다.

**왜 필요한가.** 검출기는 키프레임마다 따로 돌아서, 차는 월드 좌표에 고정인데도 박스가 프레임마다 흔들리고 어떤 프레임에서는 아예 빠진다. 시점·가림·거리가 바뀌며 점 패턴이 달라지고, 점수가 임계값 근처를 들락거리기 때문이다.

실측: **박스 690 개가 실제로는 물체 77 개**였다. 1 장에만 나타난 군집은 평균 점수 **0.16**, 10 장 이상 나타난 군집은 **0.33** 이었다 — 깜빡이는 것은 대개 점수가 낮다.

### 모양 검사

관측 횟수로는 벽·기둥이 안 걸러진다 — 일관되게 잘못 검출되기 때문이다. 모양으로 가린다.

| 기준 | 값 | 탈락 |
|---|---|---|
| 차 지붕(2 m) ~ 천장 사이에 점이 있는가 | 비율 > 1.0 → 수직 구조물 | 1 개 |
| 박스 양 끝 너머로 점이 이어지는가 | 비율 > 0.6 → 벽 | 3 개 |
| 차 높이대 점이 충분한가 | 50 개 미만 | 3 개 |

지면 −1.93 m, 천장 3.09 m 는 데이터에서 자동으로 구한다.

**임계값을 두 번 잘못 잡았다.** 처음에는 "지면 위 2.4 m 를 넘는 점" 으로 쟀는데, 실내라 **모든 차 위에 천장이 있어** 43 개 중 38 개가 탈락했다. 차 지붕과 천장 **사이 구간**을 보도록 고쳤다. 그다음 비율 임계값 0.25 도 빡빡해 24 개가 탈락했다 — 실측하니 진짜 차는 0.0~0.5, 기둥은 3 이상이어서 **1.0** 으로 올렸다.

### 다듬기가 박스를 오히려 망가뜨린 문제 (설계 수정)

처음 돌린 결과는 깜빡임은 사라졌지만 **박스가 차에서 밀려 있었다.** 구현 버그도 몇 개 있었지만, 근본 원인은 **설계**였다.

원본 검출은 **그 프레임의 센서 좌표에서, 그 프레임의 점으로** 계산된다. 오차는 검출기 오차 하나뿐이다. 그런데 다듬기는 박스를 **월드 좌표로 옮겨 평균**낸다. 그 변환에 쓰는 것이 ego pose, 즉 오도메트리이고 여기에 드리프트가 있다.

| | 오차 구성 |
|---|---|
| 원본 박스 | 검출기 오차 |
| 월드 평균 박스 | 검출기 오차(평균되어 줄어듦) **+ ego pose 오차 (원본엔 없던 것)** |

20 초 주행에서 같은 차의 월드 좌표가 프레임마다 10~30 cm 어긋나고, 더 나쁜 것은 **yaw** 다. 위치는 프레임마다 점에 다시 맞출 수 있지만 방향은 전 구간 평균이라 누적된 heading 드리프트를 그대로 안는다. 4.5 m 박스에서 5° 면 모서리가 20 cm 움직인다.

**깜빡임을 없애려고 월드 평균을 쓴 대가로 오도메트리 오차를 박스에 집어넣은 것이다.** 임계값 조정으로 해결되는 문제가 아니다.

#### 고친 방식 — 판별은 다듬기에서, 기하는 원본에서

다듬기가 잘하는 일과 못하는 일을 분리했다.

| | |
|---|---|
| 다듬기가 **잘하는 일** | 어떤 물체가 진짜인지 판별(오탐 제거), 검출이 빠진 프레임 채우기, 트랙 ID 부여 |
| 다듬기가 **못하는 일** | 박스 기하 — 오도메트리 오차가 섞여 원본보다 나빠진다 |

그래서 **그 프레임에 원본 검출이 있으면 기하를 원본 그대로 쓰고, 없는 프레임만 평균 박스를 전파**한다 (`--no-keep-raw` 로 예전 동작으로 되돌릴 수 있다).

| | 박스 수 |
|---|---|
| 원본 기하를 그대로 쓴 것 | **393** |
| 전파로 채운 것 (그중 점에 맞춘 것 105) | 148 |

**박스가 점을 감싸는 정도** (1 에 가까울수록 딱 맞음):

| | 길이축 | 폭축 |
|---|---|---|
| 원본 검출 | 0.559 | 0.689 |
| 월드 평균 (처음 방식) | 0.579 | 0.639 |
| **원본 기하 유지 (현재)** | **0.580** | **0.686** |

원본과 같은 맞춤 품질을 유지하면서 트랙 ID 와 안정성을 얻는다.

#### 같이 고친 구현 버그

| | 무엇이 틀렸나 | 고친 방법 |
|---|---|---|
| 5 단계 z 구간 | `center[2]` 를 박스 **중심**으로 봤다. mmdet3d 관례는 **바닥중심**이라 차 아래 **지면 점**이 외접 사각형에 섞였다 | `바닥+0.3 ~ 바닥+h`. 재측정 성공 33 → **40/43** |

### 남은 오차는 검출기 것이다
